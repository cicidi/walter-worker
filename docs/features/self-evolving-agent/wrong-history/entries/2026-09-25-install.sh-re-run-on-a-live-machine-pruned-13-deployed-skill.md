# install.sh re-run on a live machine pruned 13 deployed skill mirrors

**What happened:** Re-running setup/install.sh --global on the development machine, answering the skill prompt with the default (None), retired 13 of 17 deployed commands/*.md and the matching opencode instructions/*.md. The machine health check recorded it at 09:59: cmds went 17 to 5 within 26 seconds.

**Root cause:** The prune diffs the previous manifest against what this run claimed. A run that selects no skills claims none of them, so all of them looked retired. update.sh re-invokes the installer with None as the default answer, which is how a routine update could do the same thing.

**How it was discovered:** auto-worker health check

**Impact:** 13 skill mirrors lost on the development machine; skills themselves intact.

**Fix:** Answering None carries the previous bundle skills forward instead of pruning them, and update.sh passes the recorded selection back via install.sh --skills so the question is not asked at all.

**Prevention rule:** A prune must never retire paths the previous run claimed and this one did not select. Answering "skip skills" means do not install them, not remove the ones present. Before re-running setup/install.sh on a live machine, know what its prune will retire: it rewrites the manifest to claim only what this run produced, and everything else the old manifest claimed is removed.

**Anti-pattern:** Not following the prevention rule above
