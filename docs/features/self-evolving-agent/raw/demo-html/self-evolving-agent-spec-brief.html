KEY POINT

The PRD defines what (R1–R7, three-tier model, safety). This spec defines how: mem0 = memory substrate (library mode), Hermes = loop patterns (re-hosted on our hooks), dual-IDE capture = multi-trigger + audit + reconciliation.

1 · Architecture

  1. Claude Code / OpenCode → tool calls captured by hooks (PostToolUse + SubagentStop + Stop).
  2. Per-turn: extract lessons → mem0.add (+ optional state_delta). Non-blocking.
  3. Session-end: full transcript → DeepSeek Flash → reconciliation + skill-create assessment.
  4. Session start: mem0 snapshot → CLAUDE.local.md (zero tool calls).

LLM policy: DeepSeek Flash everywhere. Embedder: local (fastembed/BGE). Fallback: Gemini → Claude Haiku.

KEY POINT

Per-turn does NOT reprocess history. Each turn extracted once. Cross-turn dedup + pattern detection = session-end only.

Hermes pattern adapted: "smart approval system" → staged review by default (auto_approve: false). Safety: circuit breaker (>3 skills/24h), sandbox dry-run, rollback.

5 · Context Injection

Session start: mem0 snapshot → CLAUDE.local.md markers. Both IDEs read at start — zero tool calls (R5). MEMORY.md reclassified as curator-generated read-only export for git diffability.

6 · Pending Queue (v1)

Skills staged to ~/.coworker/pending/. Batch approve/reject. 30-day auto-expiry (never silently promoted). Quality scoring deferred to v2.
