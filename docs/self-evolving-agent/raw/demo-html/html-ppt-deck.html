大家好。今天介绍 Self-Evolving Agent PRD v6——一个在使用中自我进化的 AI agent。核心理念是：进化不应该是一个独立的模式或训练流程，而是嵌入在日常使用中。你正常使用 Claude Code 或 OpenCode，后台静默捕捉经验、创建技能、积累记忆。下一次使用时，agent 就更聪明了。

SDK Mode · 程序化入口

Explicit Loop for Automation

For CI/CD, batch processing, scheduled autonomous runs. Default max: 12 hours.

Termination Conditions — loop stops when ANY is met

1

Goal achieved

User-provided success criteria evaluated true (e.g. pytest returns 0)

success
2

Stagnation

3 consecutive cycles produce no new changes (no diff, no skill, no memory)

dead end
3

Time expired

12h max reached. Graceful stop: save state, run summarization, exit.

timeout
4

Human halt

Human confirms "done" or "stop" — immediate graceful termination.

manual

One cycle = Observe → Decide → Spawn agent → Record. Without loop flag, one cycle runs and exits.

Degrade, don't crash — retry with backoff, record gaps, defer on outage
除了隐式进化，我们还提供了一个显式的 SDK Mode，用于 CI/CD 和定时任务。12 小时默认超时，四种终止条件只要满足任意一个就停。One cycle 是 Observe-Decide-Spawn-Record。错误恢复策略是"降级不崩溃"——重试 3 次、记录 gap、延后同步。最重要的是，它自动更新的只有 CLAUDE.local.md 和技能，CLAUDE.md 永远不会被自动修改。

三层记忆是这次设计的核心。Tier 1 是当前 session 的工作记忆，自动捕获，不需要手动保存。Tier 2 是项目状态——记录做了什么、对错、进度，存在 initiative state 文件里。Tier 3 是跨项目、跨 session、永久的长期记忆——教训、模式、约定、用户偏好。数据流是：每次 turn 同步 state，session 结束时 LLM 做 summarization（主要路径），snapshot 在 session 开始时注入。R1 到 R7 这七个需求每一个都被这三层覆盖了。

Knowledge · 知识分类

Three Types of Knowledge

Each maps to a memory tier, each has its own trigger and lifecycle.

SOP

可重复的操作流程

Step-by-step procedures for specific tasks

Example: "Fix lint errors", "Deploy checklist"
Tier: Skill store → promoted to skill-factory
Trigger: Post-task assessment → skill-create
↑ Shared across users
经验

对/错的教训

Lessons, patterns, pitfalls through experience

Example: "MCP first request always 403", "ruff E501 ignored"
Tier: Tier 3 Long-Term Memory (permanent, cross-project)
Trigger: Per-turn sync + session-end LLM summary
↑ Personal, durable
State

当前进度

Where we are: done, pending, blocked, who, when

Example: "Dashboard 5 pages, 2 done, 2 pending, 1 blocked"
Tier: Tier 2 State files (docs/<initiative>/state/)
Trigger: Every turn / every phase completion
↑ Archived on completion
SOP — how to do it | 经验 — what happened | State — where we are
Agent 产生三种知识。SOP 是"怎么做"——可重复的操作流程，最终晋升到 skill-factory 共享给所有人。经验总结是"发生了什么、学到了什么"——跨项目永久保留在 Tier 3。State 是"当前在哪"——项目完成就归档。这个分类让每种知识有清晰的归属、触发机制和生命周期。

State Engine · 状态引擎

Recording Criteria

Three dimensions — record if ANY one is met. State recording is a side effect of using the IDE.

Three Dimensions

做了什么 What was done

Concrete output: code, docs, config, research conclusion, external action

对/错 Right & wrong

Lessons: what worked, bugs found, blind spots, compaction risks

进度 Progress tracking

Done/not done, who, when, dependencies

Always vs Never Record

Always record

  • Code / doc / config changes
  • System events (MCP setup, model config, backup/restore, compaction)
  • Research with conclusions
  • Failed attempts
  • Subagent conclusions

Never record

  • Instant queries (just looking)
  • Single-command atomic ops
  • Pure chat / curiosity
  • Transient status checks
State file: docs/<initiative>/state/YYYY-MM-DD-state.md — live document, updated continuously, can modify previous entries
Every turn → capture fires → platform writes to state file
状态引擎的三个维度——做了什么、对错、进度——只要满足任意一个就记录。Always record 包括代码变更、系统事件、有结论的研究、失败尝试、子 agent 结论。Never record 包括瞬时查询、单命令原子操作、纯聊天、临时状态检查。State file 是一个活文档，持续更新，可以修改之前的条目，每个 phase 完成时强制更新。

Evolution Engine · 进化引擎

Create, Patch, Summarize

Three mechanisms drive continuous improvement. All default to review mode.

1

Auto Skill Creation

Primary trigger: Post-session — background LLM summarizes transcript, identifies reusable workflows, invokes skill-create.

Secondary: In-session, when a task has 10+ tool calls.

Skills start local (0–9 uses) → promote to skill-factory (10+ uses). Pending queue with batch approve/reject, auto-expire at 30 days.

Dual trigger
2

Auto Skill Patching

Using an existing skill and discovering it's outdated, incomplete, or wrong → invoke skill-edit (surgical: old_string → new_string).

patch_count feeds curator decisions and promotion. Rollback available. Quality metrics: error_rate, patch_frequency, user_override_rate.

Surgical edits
3

Post-Session Summarization

Central mechanism. Session ends → single LLM pass over full transcript produces two outputs:

1. Lessons/patterns/pitfalls → Tier 3 memory
2. Reusable workflows → stage via skill-create

Remote background LLM by default; local opt-in for sensitive sessions.

One pass, two outputs
Lifecycle: active → stale (30d unused) → archived (90d) | Curator: periodic idle cleanup
进化引擎的三个机制。Auto skill creation 有双触发器——post-session 是主要的，in-session 是辅助的。Skills 先在本地成长，用到 10 次以上才考虑 promotion。Auto skill patching 是外科手术式的编辑，patch_count 用于决策。Post-session summarization 是核心——一次 LLM pass 产生两个输出：教训到 Tier 3，可复用工作流到 skill-create。默认使用远程 LLM 做摘要，敏感 session 可以选择本地模型。

Guardrails · 安全与效能

Safety Architecture + Effectiveness Metrics

Safety

Circuit breaker

>3 skills created/patched in 24h → halt all auto-evolution

Sandbox testing

Dry-run pending skills in sandboxed session before promotion

Rollback

Auto-rollback if post-patch error rate > pre-patch by 50%+

Review mode default

All self-evolution defaults to review; auto-approval is opt-in, scoped per operation type

Effectiveness

skill_reuse_rate ↑ rising

Fraction of sessions invoking an auto-created skill

user_correction_rate ↓ falling

User overrides/corrects the agent per task

task_first_pass_rate ↑ rising

Tasks completed without rework

memory_hit_rate ↑ rising

Searches returning a useful entry

Safety metrics tracked per session: refusal_rate, unsafe_output_rate, skill_error_rate, circuit_breaker_trips — feed into curator decisions

Why safety matters: Shanghai AI Lab (2026) + AgentWorm (Peking Univ, 2026) documented real self-evolution safety erosion
安全性方面，我们引用了上海 AI Lab 2026 年的研究——自我进化在四个路径上都出现了安全侵蚀。所以我们设计了四层防护：熔断器、沙箱测试、回滚机制、默认审查模式。效能指标方面，四个关键指标跟踪 agent 是否真的在变聪明：技能复用率上升、用户纠正率下降、首次通过率上升、记忆命中率上升。这些数据自动采集，在 curator 报告中呈现。
