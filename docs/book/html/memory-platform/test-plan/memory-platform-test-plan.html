Memory Platform — Test Plan

Each case names the requirement from the PRD it covers and the test that implements it at commit a0f4ce0. The tests named below are mocked: the language model and mem0 are replaced, so they make no outside call and need no key. Some of the same files also hold key-gated tests. Tests marked real call DeepSeek when DEEPSEEK_API_KEY is set and are skipped otherwise. Tests marked integration use the real mem0 store under the user's home folder and are skipped when mem0 is not configured. No case below relies on a key-gated test.

Not covered today: a dump with invalid values (QUES-A), concurrent merges (QUES-B), a damaged graph.json (QUES-C), and the wrong-history commands run from another folder (QUES-F). Also not covered: capture and merge repeated on every turn (QUES-I), edges of a folded node (QUES-J), a locked Qdrant store during capture (QUES-K), and capture outlasting the hook time limit (QUES-L). The open questions are in the design.

Test Execution Order

Run tests/memory/test_graph_core.py and tests/python/test_mem0_client.py first, because the stores underlie everything else. Then capture, curator, injection, safety, and knowledge tests, then the memory classes in test_cli.py.

Expected Pass Threshold

Every mocked test named in a case must pass; the threshold is 100%. A skipped test counts as not run: it neither passes nor fails a case, and it never counts toward the 100%. So a run without a key verifies nothing about the key-gated tests. A run with a key and a configured mem0 should also pass them, but no case depends on that. TST-H has no test, so PRD-H is not verified.
