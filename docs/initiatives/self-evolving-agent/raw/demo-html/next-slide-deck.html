Memory Platform + Self-Evolution Engine

An autonomous agent that captures every turn, builds long-term memory with mem0,
and evolves its own skills in a continuous closed learning loop.

How It Works

  1. 1 Capture — Dual-IDE hooks (PostToolUse, SubagentStop, Stop) fire on every tool call. OpenCode too.
  2. 2 Extract — DeepSeek Flash processes each turn: tool event + recent window + mem0 recall. Outputs 0..N lessons + optional state delta.
  3. 3 Evolve — Hermes loop patterns: create skills after 10+ tool calls, patch outdated skills, curator runs weekly to manage lifecycle.
  4. 4 Inject — Frozen memory snapshot written to CLAUDE.local.md at session start. Both IDEs read it with zero tool calls.

Three-Tier Memory Architecture

  • Tier 1 — CLAUDE.local.md
    Injected context snapshot. Frozen at session start. Both Claude Code and OpenCode read it automatically — zero tool calls. Mid-session mem0 writes do not refresh the active snapshot.
  • Tier 2 — State Files
    Per-turn progress tracking in docs/<init>/state/. State deltas appended incrementally. Human-readable, git-tracked.
  • Tier 3 — mem0 Substrate
    Long-term knowledge store. Hybrid retrieval: semantic (vector) + BM25 (keyword/exact) + entity matching. DeepSeek Flash extracts facts. Local embedder — no OpenAI dependency.

Requirements R1 – R4

  • R1 — IDE-Agnostic
    Works with both Claude Code and OpenCode as first-class citizens. mem0 state lives in ~/.coworker/memory/, not any IDE's config directory.
  • R2 — Per-Turn Persistence
    No manual save required. Hooks call memory.add() automatically after every tool call. Multi-trigger + audit trail ensures data is never lost.
  • R3 — Cross-Session Search
    Exact + semantic hybrid retrieval via mem0. Find lessons by keyword, by meaning, or by structured metadata (project + topic + problem) — all in one query.
  • R4 — Agent-Managed Notes
    The agent writes, patches, and removes its own knowledge entries. Full CRUD: memory.add / update / delete via mem0 API.

Requirements R5 – R7

  • R5 — Frozen Snapshot
    Memory read from mem0 at session start and injected into CLAUDE.local.md between markers. Captured once; mid-session writes do not refresh it. Manual refresh available for sessions longer than 2 hours.
  • R6 — Periodic Cleanup
    Weekly curator run marks stale entries, archives entries untouched for 90 days. Entries carry state and last_used metadata. No cruft accumulation.
  • R7 — No Background Server
    mem0 runs in library mode (pip install mem0ai). In-process Qdrant vector store. No Docker. No always-on process. Zero infrastructure overhead.

Self-Evolution Engine

Skill Creation

After 10+ tool calls in a session, assess the transcript for reusable workflows. Invoke skill-create with session context. Two triggers: in-session (task complete) and post-session (Stop reconciliation pass). Staged to pending queue for review.

Skill Patching

When a skill is invoked and found outdated or wrong, invoke skill-edit with surgical old_string → new_string. Patch count feeds the curator. Same staged approval model.

Curator

Runs every 7 days after 2h+ idle. Lifecycle: active → stale (30 days) → archived (90 days). Tracks use_count, patch_count, error_rate. Never touches hand-written or skill-factory bundled content. Recovery via unarchive.

Smart Approval

Staged review by default. Per-domain opt-in to auto-approve only for low-risk operation types. Safety gates enforced: circuit breaker (>3 skills / 24h), sandbox dry-run before promotion, rollback capability.

Safety Architecture

  • Circuit Breaker
    More than 3 auto-created skills in any 24-hour window halts all auto-evolution. Pending queue is preserved. User must run coworker skill resume to re-enable.
  • Staged Review Pipeline
    All auto-created and auto-patched skills go to ~/.coworker/pending/skills/. Batch approve or reject. Items untouched for 30 days are auto-rejected — never silently promoted.
  • Sandbox + Rollback
    Dry-run verification before any skill is promoted to active. coworker skill unarchive and coworker memory unarchive for one-command recovery.
  • Source of Truth
    Raw session transcripts in analytics.db are ground truth. mem0 is derived. If mem0 is corrupted, re-extract from transcripts — no data loss is possible.

Scope

In Scope

  • mem0 memory substrate (library mode)
  • Dual-IDE capture (Claude Code + OpenCode)
  • Self-evolution loop (Hermes patterns)
  • Simple pending queue (review + approve)
  • Evolution metrics (7 KPIs)

Out of Scope

  • QA / auto-worker agent
  • GEPA / DSPy prompt evolution
  • Quality scoring v2
  • OpenCode subagent hook equivalent
  • Cloud / hosted mem0 server
